### Issue 4: DATABASE vs USER SCHEMA
**Your Existing Schema** (from user request):
```sql
sub_event_registrations (
  id, created_at, sub_event_id, ticket_id, status, 
  attended_at, checked_in_at, college
)
```

**Expected Schema** (for track registration):
```sql
sub_event_registrations (
  id, created_at, sub_event_id, name, email, phone,
  college, notes, payment_method, payment_status,
  payment_id, registered_at, checked_in, checked_in_at,
  rating, feedback
)
```

**Conflicts**:
- ❌ You have `ticket_id` - Not needed for track registration
- ❌ You have `status` - Should be `payment_status`
- ❌ You have `attended_at` - Should use `checked_in_at` + `checked_in` boolean
- ✅ You have `college` - Good
- ❌ Missing: name, email, phone, notes, payment fields
